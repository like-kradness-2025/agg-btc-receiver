- 前提: **現行を分割するのではなく、完全新規の構造（`receiver-v2/`）を作る** ✓

## 1. 構造（3プロセス＋共通の監視）
| プロセス | 責務 | 所有者（決定権） |
|---|---|---|
| **ingest（受信）** | WS接続・購読・venue差の吸収・keep-alive・再接続 | 接続世代・購読状態・受信メタ（`recv_ts_ms`/`recv_mono_ns`/`connection_id`/`receive_seq`）|
| **organize（整理）** | raw の耐久化・重複排除・並び順の確定・watermark・遅着・backfill | 耐久化境界・ACK・再開 cursor・欠測の確定 |
| **book（板更新）** | 板の維持・同期境界の証明・diff 適用 | 同期境界・世代判定・fail-closed 判定 |
| **supervisor（共通）** | 起動・監視・停止・readiness 判定 | プロセスの生存・停止順 |

- **役割の独立性**: 板が止まっても受信・整理は止まらない ✓（整理は板の状態を参照しない ✓）
- **停止順**: 受信 → 整理 → 板 ✓（受信を先に止めて末尾を確定 ✓ 整理が全ACK確認後に正常終了マーカー ✓）
- **移行スイッチは作らない** ✗（`RECEIVER_SPLIT_MODE` のような段階切替は不要 ✓ — v2 は独立実装 ✓）

## 2. 契約（プロセス間）
- **envelope**（実装済 ✓ `src/envelope.mjs`）: `recv_ts_ms`（socket境界・不変 ✓）／`recv_mono_ns`（接続内の順序 ✓）／`(connection_id, receive_seq)`＝**再送を no-op にする鍵** ✓／`raw` は生バイトが正本 ✓
- **IPC**: UNIX domain socket・**uint32 長プレフィクスのフレーム**（実装済 ✓）／バッチ 512件 or 100ms ✓／ACK は**非同期・連続耐久範囲の上限のみ** ✓（穴があればそこで止める ✓）
- **spool**: market 別の追記専用セグメント（64MB ✓）／`O_APPEND`＋1秒 fsync ✓／古い順に流す ✓／上限＝空き5% or 2GB ✓
- **耐久化（テーブル3つ ✓）**: `pending_boundary`（watermark と同一tx ✓）／`received_tail`（1秒or1000件ごとの下限 ✓）／`run_marker`（起動時に旧世代を無効化 ✓ 正常終了時のみ現世代を complete ✓）
- **バックプレッシャ**: メモリキュー → spool → **受信停止＋欠測記録** → 記録不能なら**非ゼロ exit** ✓
- **不変条件（守る順）**: ①世代・購読順序・欠落/二重適用なし・**旧世代の同期結果は拒否**・**fail-closed** ②受信メタは不変・**耐久化前に ACK/再開位置を進めない**・再送は冪等・満杯でも黙って捨てない ✓

## 8. 壁打ち（luna）反映

### 8.1 クラッシュ時の復旧順と重複排除の一貫性（**順序を契約にする**）
- 整理は必ず **①spool へ追記（fsync）→ ②DB へ確定（単一tx）→ ③ACK を返す** の順 ✓
- **ACK は DB 確定より先に出さない** ✗ → ①と②の間で落ちても **ACK されていない＝再送される** ✓ → `(connection_id, receive_seq)` の**重複排除で吸収** ✓（一貫性は「再送が no-op」で担保 ✓）
- 起動時の復旧順: **未 flush の spool を先に流して耐久化** ✓ → `received_tail` と照合 ✓ → 埋められない範囲を**欠測として確定** ✓（fail-closed ✓）
- `received_tail` は**下限**であり、単独では完全性の証明にならない ✗（マーカーは `run_marker` のみが与える ✓）

### 8.2 世代の権限を一本化（**二重化させない**）
- **接続世代を発行するのは `ingest` だけ** ✓（接続＝1世代 ✓）
- **`book` は受け取ったデータに付いた接続世代だけを信頼** ✓し、**superseded（置き換え済み）なら拒否** ✓
- `book` が持つ「板の同期世代」は**接続世代の再定義ではない** ✗（同一接続内の同期手続きの同一性 ✓）
- 境界を渡るデータには**必ず接続世代を載せる** ✓（載っていないデータは受け取らない ✗）
- 判定が割れた場合の優先は **`ingest` の接続世代** ✓（板は従う ✓）

### 8.3 切替判定に**障害経路の実地通過**を必須化
- 24時間の併走だけでは**未経験の経路を通過扱いにしてしまう** ✗ → 併走期間中に**強制的な障害訓練**を行う ✓
  1. **`ingest` を再起動**（受信断 → 再接続 → snapshot 再同期 ✓）
  2. **spool 溢れを意図的に起こす**（メモリキュー満杯 → spool → 復帰 ✓）
  3. **`book` を単独再起動**（境界証明まで diff 適用禁止 → 復帰 ✓）
- 各訓練で確認するもの: **欠落0・重複0・fail-closed が実際に働いた記録** ✓（`data_complete` の正しさ ✓）
- **未通過なら切替しない** ✗（通過した障害経路だけを「経験済み」と数える ✓）

## 9. 監査（Astra）反映

### 9.1 organize → book の配送契約（**未適用を失わない**）
- `book` は**適用済み位置を自ら耐久化**する ✓: `applied_boundary(market, stream, connection_id, up_to_receive_seq)` ✓
- 再起動時、`book` は organize へ**「この位置から再送」**を要求 ✓（位置は `applied_boundary` ✓）
- organize は **`applied_boundary` の受領まで、その範囲を破棄しない** ✗（受領後に解放 ✓）
- **保持期限**（既定: 5分 or 1GB の先に達した方 ✓）を超えた場合、organize は**欠測として確定** ✓し、book は fail-closed で境界を取り直す ✓
- 再送は `(connection_id, receive_seq)` で**重複排除＝no-op** ✓（何度でも安全 ✓）

### 9.2 不明な末尾と完全性の回復条件
- **`received_tail` より後の不明区間**は、照合では検出できない ✗ → **区間として記録**する ✓
  - 開始 = `received_tail` の値 ✓／終了 = 再開時刻（正常終了マーカーが無い場合 ✓）
  - この区間は `data_complete=false` ✓（**欠測の疑い**として扱う ✓）
- **回復条件**: 受信が**再購読＋snapshot で新たな連続性を確立した時点**から完全性を再開 ✓
  - **回復できない過去区間は欠測のまま残す** ✗（消さない ✓＝「無かったこと」にしない ✓）
- `received_tail` の更新間隔（1秒 or 1000件 ✓）が**疑い区間の最大幅**になる ✓ → 設計値として明記 ✓

### 9.3 切替・ロールバックの**データ連続性**（ユニット交換だけでは不十分 ✗）
- **下流の読取先**を切替時に明示する ✓（v1 の出力先 → v2 の出力先 ✓）
- **cursor の引き継ぎ**: 下流は「**切替時刻の直前の確定位置**」から再開 ✓（切替時刻を1つの境界値として共有 ✓）
- **重複書き込みの防止**: v2 は**切替時刻より後だけ**を書く ✓（v1 が書いた範囲を再書きしない ✓＝開始位置を明示して起動 ✓）
- **ロールバック時**は同じ規則を逆に適用 ✓（戻し時刻以降は v1 が書き ✓、v2 のその期間は未使用として扱う ✓）
- 切替・復帰は**1つの原子操作**で表現する ✓（境界レコード1件＝切替時刻＋書込先 ✓）→ 途中状態を作らない ✗

### 9.4 再監査（Astra）反映 — §9 の詰め直し

**(1) §9.1 の穴: 記録が状態より先に進むと再送が no-op になり、未復元の適用結果を失う** ✗
- `applied_boundary` は**板の状態更新と同一の単一tx**で書く ✓
  → **記録が状態より先行することを禁止** ✗（「適用済みと記録されたが板に反映されていない」状態を作らない ✓）
- 記録が**状態より遅れる**のは許容 ✓ → その場合は再送が**再度適用される** ✓＝**適用処理は冪等でなければならない** ✓（`(connection_id, receive_seq)` の範囲適用は同じ結果になること ✓）
- クラッシュ時: 記録が遅れているだけなら再送で復元 ✓／記録が先行していたらそれは**契約違反**として検出（起動時に板と記録を照合 ✓）

**(2) §9.2 の穴: 区間の終端は「再開時刻」ではなく「連続性回復時点」** ✗
- 疑い区間の終端 ＝ **再購読＋snapshot で連続性が確立した時点** ✓（プロセス再開時刻ではない ✗）
- したがって**区間の幅は更新間隔では抑えられない** ✗ ＝ **停止〜再購読〜snapshot 証明までの実時間**が幅になる ✓
- 記録は「**開始 = 最後に確定した `received_tail`** ✓／**終了 = 連続性回復時点** ✓」✓（幅の上限は前提にせず、実測として残す ✓）

**(3) §9.3 の穴: 旧側の停止境界・境界時刻ちょうどの所属・新旧 cursor の対応** ✗
- 切替の手順を順序として固定する ✓
  1. **旧側を確定点で停止** ✓（drain＋flush 後に **`last_settled`** を記録 ✓）
  2. **境界レコードを1件**書く ✓（`switch_ts`・旧側 `last_settled`・新側 `start_from` ✓）
  3. **新側は `start_from` より後だけを書く** ✓（旧側の書いた範囲を再書きしない ✓）
  4. **境界時刻ちょうどの所属を1つに決める** ✓（旧側＝以下 ✓／新側＝超 ✓＝二重にも欠落にもしない ✓）
  5. **旧形式 cursor → 新形式 cursor の対応**を切替時に確定し**記録**する ✓（対応不能なら境界から再開 ✓）
- 「境界レコード1件」だけでは不足 ✗ → **①〜⑤の順序と各記録が揃って初めて欠落・重複を防げる** ✓

### 9.5 切替順序の確定（Astra 再指摘の解消）

**(3) の穴: cursor 対応の確定・記録が「新側の書込み開始」より後にあると、途中クラッシュで再開位置が保証されない** ✗
→ **対応の確定・永続化を、新側の書込み開始の"前提条件"にする** ✓

**確定した順序（この順序自体が契約 ✓）**
1. **旧側を確定点で停止**し、drain＋flush 後に **`last_settled`** を記録 ✓
2. **cursor 対応を確定して永続化** ✓（**新側の書込み開始の前提条件** ✓＝これが無い限り新側は書かない ✗）
3. **境界レコードを1件**書く ✓（`switch_ts`・`last_settled`・`start_from`・**対応ID** ✓）
4. **新側の書込み開始** ✓（`start_from` の**直後から** ✓）
5. **境界時刻ちょうどの所属**: 旧側＝**以下**（`last_settled` まで含む ✓）／新側＝**超**（`start_from` は含まない ✓）

**cursor の具体（包含・排他まで）**
- 旧形式: `(ファイルID, バイト位置, 排他 ✓)`
- 新形式: `(market, connection_id, receive_seq, 排他 ✓)`
- 対応表は**切替時に確定して永続化** ✓（後から推測しない ✗）

**対応不能だった場合（具体）**
- `start_from = last_settled の直後` とする ✓
- **起動時に検証**: `start_from` が**新側の書くすべての位置以下**であること ✓（満たさなければ**起動しない** ✗）
- 重複は重複排除で no-op ✓／欠落は「`start_from` ≤ 全書込み位置」の検証で防ぐ ✓

**クラッシュ位置ごとの安全性**
- ②の前 → まだ何も書いていない ✓（安全 ✓）
- ③の前 → 対応は永続化済み・未使用 ✓（再開時に再利用 ✓）
- ④の後 → 境界は記録済み ✓
- → **どの時点で落ちても「新側の再開位置が一意」** ✓

### 9.6 切替方式の変更 — **cursor を写像しない（エポック境界方式）**

**なぜ変えるか**: Astra の指摘は同じ根を指していた ✓ = **旧側の位置（ファイルID・バイト位置 ✓）を新側の位置（`market, connection_id, receive_seq` ✓）へ写すことは原理的にできない** ✗
→ 写像をやめ、**切替を「時刻の境界」で定義**する ✓（**両者に共通に存在するのは受信時刻だけ** ✓）

**エポック境界の定義**
- 切替は**1つの時刻 `epoch_ts_ms`** で表す ✓（`switch_ts` と同一 ✓／境界レコード1件 ✓）
- **所有権**: 旧側は **`recv_ts_ms ≤ epoch`** ✓／新側は **`recv_ts_ms > epoch`** ✓（**各時刻の所有者はただ1つ** ✓ → 二重にも欠落にもならない ✓）
- **先頭を飛ばさない** ✓: 新側の最初に書くレコードは「**`recv_ts_ms > epoch` を満たす最初の受信フレーム**」✓
  → 旧側は `epoch` まで（drain＋flush 済 ✓）を覆っているので、**区間は連続する** ✓（間に落ちる時刻が存在しない ✓）
- **cursor の意味を変える** ✓: 下流の再開位置は **`(epoch_ts_ms, writer)`** ✓（バイト位置の対応付けはしない ✗）
  - 下流の再開規則: 新側のストアでは「**`recv_ts_ms > epoch_ts_ms` を満たす最初のレコード**」から ✓（**述語による探索** ✓＝位置変換ではない ✓）

**開始位置の検証（下限確認ではない ✓）**
- 検証は**述語**で行う ✓: `min(新側が最初に書いたレコードの recv_ts_ms) > epoch_ts_ms` ✓ **かつ** `epoch_ts_ms ≥ 旧側が書いた最後の recv_ts_ms` ✓
- これは**被覆（coverage）の確認** ✓であり、単なる下限比較 ✗ ではない ✓ → **間の区間の存在を検出できる** ✓
- 加えて新側**自身の連続性**（`receive_seq` の連続・欠落なし ✓）を起動時に確認 ✓

**④以降のクラッシュ時の再開規則（未定義だった点 ✓）**
- 境界レコードは**開始位置と所有権だけを定める** ✓（再開位置は定めない ✗）
- **再開は「新側自身が耐久化した位置」から** ✓（整理の `applied_boundary`／受信の `received_tail` ✓＝§9.1・§9.2 の規則をそのまま使う ✓）
- したがって④以降のどの時点で落ちても、**再開位置は新側の記録から一意に決まる** ✓（境界レコードを再解釈しない ✓）

**旧 cursor の対応が取れない場合（具体）**

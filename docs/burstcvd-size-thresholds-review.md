## 3. 運用観点での評価軸

### 3.1 ダッシュボード表示（CVDライン）

3本の CVD ライン（Small/Medium/Large）を同一チャートに描画する場合：

- **Large ラインの視認性**：Large イベントが窓の 5%（p95基準）だと、1時間チャート（120窓）で約6回。ラインが「階段状」になりやすく、視覚的な連続性が低い。10-12% で約12-14回なら、ラインとして十分な密度。
- **ライン間の分離**：3本のラインが似た振幅だと識別困難。Small と Medium の差、Medium と Large の差が明確であるべき。
- **色の意味付け**：緑（Small）= retail noise、黄（Medium）= active flow、赤（Large）= market-impact flow という直感的な配色。赤が頻繁に出ると「警告疲れ」する。

### 3.2 アラート通知

- **Large = 10% をアラートに使うのは多すぎる**：窓の 1/10 でアラートが発報 → 1時間に12回。通知疲れ必至。
- **アラート専用閾値の分離が必須**：可視化用の「Large」とアラート用の「Critical Spike」は別物。
- 推奨：アラートは **p95（Top 5%）** または **p97（Top 3%）** で設計する。

### 3.3 解釈性（Interpretability）

- 15,000 / 120,000 は「中途半端な数字」。ダッシュボード凡例に `≥$15,000` と書かれても、それが「多い」のか直感的にわからない。
- 10,000 / 100,000 は誰でも理解できる。BTC建てに換算しても綺麗（$100K/BTC で 0.1 BTC / 1 BTC）。
- Spot / Perp の比が **厳密に 1:10** であることも理解しやすい（Perp は Spot の約10倍のフロー）。

### 3.4 False Positive 耐性

- 「Large」が多すぎる（>15%）→ 意味が薄れる。「赤が出た」の価値が下がる
- 「Large」が少なすぎる（<3%）→ ほぼ常にゼロで、ラインとして機能しない。Whale 専用にすべき
- **最適範囲は 8-12%**。意味があるが多すぎない。

## 4. 推奨閾値

### 4.1 本推奨：スキーム C（10K/100K + 100K/1M）— 解釈性重視

**ダッシュボード可視化用の3段階：**

| Level | Spot (USD) | BTC換算 | Perp (USD) | BTC換算 | Spot % | Perp % |
|-------|-----------|---------|-----------|---------|--------|--------|
| **Small** | < $10K | < 0.1 BTC | < $100K | < 1 BTC | 43.5% | 39.6% |
| **Medium** | $10K – $100K | 0.1 – 1 BTC | $100K – $1M | 1 – 10 BTC | 44.5% | 47.5% |
| **Large** | ≥ $100K | ≥ 1 BTC | ≥ $1M | ≥ 10 BTC | 12.0% | 12.9% |

**選定理由：**

1. **完璧な丸め数字**：10K/100K/1M。ダッシュボード凡例・ドキュメント・口頭コミュニケーションすべてで一貫して使える
2. **BTC心理的閾値と一致**：0.1 BTC / 1 BTC / 10 BTC（@$100K/BTC）。トレーダーが直感的に理解できる
3. **Spot:Perp = 1:10**：永続的に覚えやすい。Perp が Spot の約10倍の notional フローを持つ構造的事実とも整合
4. **Large 12% ≈ Top 12%**：十分な密度で CVD ラインを描ける。赤が出ても「またか」ではなく「お、大口だ」と感じる絶妙な頻度
5. **将来拡張性**：v2 で Whale レベルを追加する場合、Spot ≥ $1M（10 BTC）、Perp ≥ $10M（100 BTC）と自然に拡張できる

### 4.2 代替推奨：スキーム A（15K/120K + 150K/1.2M）— 統計的バランス重視

現行の p50/p90 方式。データ駆動でバランスが良く、すでに分析・検証済み。

**Small/Medium がちょうど50%ずつ**に近いのが唯一の強み。ただし数字が覚えにくい。

### 4.3 アラート用閾値（可視化とは別設計）

| Level | Spot | Perp | 発報率 | 意味 |
|-------|------|------|--------|------|
| **BurstCVD Spike** | ≥ $200K | ≥ $2M | ~5% (p95) | 大口フローの異常検知 |
| **BurstCVD Critical** | ≥ $500K | ≥ $5M | ~1% (p99) | 超大口。要即時確認 |

**重要**：アラート閾値は可視化用の Large 閾値（100K/1M）より **2-5倍高く設定する**。これにより：
- ダッシュボードの赤ラインは「頻繁に見る大口」→ コンテキスト把握用
- アラートは「本当に異常な大口」→ アクション用
- 二重のフィルターで通知疲れを防止

## 5. 推奨しない案と理由

### 5.1 Large = Top 5%（p95 基準、スキーム D/E/F）

- **ダッシュボード用途には不適**：窓の5%しかイベントがないため、Large CVD ラインが「飛び飛び」になる
- 1時間チャートで約6イベント。CVD の累積線として視覚的に貧弱
- p95 はアラート専用に取っておくべき

### 5.2 Large = Top 3% 以下（p97-p99）

- CVD ラインとして完全に機能不全。ほとんどの時間ゼロ
- Whale 専用の4段階目として別途設計すべき

### 5.3 Large = Top 15% 以上

- 「Large」の意味が希薄化。赤ラインが Medium と区別つかなくなる
- アラートに使えないことはもちろん、可視化でもノイズ化する

## 6. 実装メモ

### 6.1 既存コードへの影響

現在、BurstCVD のサイズ閾値は `scripts/analyze-burst-cvd-thresholds.py` と `scripts/compare-burst-cvd-thresholds.py` で分析のみ行われており、本番の可視化パイプラインには未実装。

新規に以下の場所で閾値を定義する必要がある：
- `lib/burst-cvd-size-buckets.mjs`（新規）：分類関数 `classifyBurstCvd(notional, group)`
- `scripts/plot-burst-cvd.py` の拡張：3色の CVD ライン描画

### 6.2 閾値の定数化

```js
// lib/burst-cvd-size-buckets.mjs (新規推奨)
export const BURSTCVD_SIZE_THRESHOLDS = Object.freeze({
  spot: { mediumMin: 10_000, largeMin: 100_000 },
  perp: { mediumMin: 100_000, largeMin: 1_000_000 },
});

export function classifyBurstCvd(absBurstDeltaNotional, group) {
  const t = BURSTCVD_SIZE_THRESHOLDS[group];
  if (!t) throw new Error(`Unknown group: ${group}`);
  if (absBurstDeltaNotional >= t.largeMin) return 'large';
  if (absBurstDeltaNotional >= t.mediumMin) return 'medium';
  return 'small';
}
```

### 6.3 BTC価格変動への耐性

閾値は USD 固定であり、BTC 価格変動により実質的なサイズ感は変化する。
- $100K/BTC → Large Spot ≥ $100K = 1 BTC
- $50K/BTC → Large Spot ≥ $100K = 2 BTC
- $200K/BTC → Large Spot ≥ $100K = 0.5 BTC

**短期（週〜月）では問題にならない**。長期（年）で閾値の再検討が必要だが、BTC 数量ベースへの切り替えは解釈の一貫性を損なうため、現時点では USD 固定を維持する。

## 7. 結論

| 観点 | 推奨 |
|------|------|
| **可視化用3段階** | Spot: **10K / 100K**, Perp: **100K / 1M**（スキーム C） |
| **Large の位置づけ** | Top ~12%。頻出しすぎず、CVD ラインとして十分な密度 |
| **アラート用閾値** | Spot ≥ **200K**, Perp ≥ **2M**（Top ~5%。可視化とは完全分離） |
| **Spot/Perp 分離** | 維持（必須）。1:10 の閾値比で統一 |
| **閾値の丸め** | 必須。10K/100K/1M の clean numbers を使用 |
| **4段階目 (Whale)** | 今回の対象外。v2 で Spot ≥$1M, Perp ≥$10M として追加検討 |

**理由の要約**：
数字がダッシュボード上で直感的（0.1 BTC / 1 BTC / 10 BTC）、spot/perp の構造的差異を反映（10:1）、Large の出現率12%は「多すぎず少なすぎず」で CVD ラインに最適、アラートは別途厳格な閾値で設計することで通知疲れを防止。

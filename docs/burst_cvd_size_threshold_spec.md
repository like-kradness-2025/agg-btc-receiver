# BurstCVD サイズ閾値 実装・契約仕様書

**版**: v1.0-draft  
**日付**: 2026-07-08  
**著**: 実装サブエージェント (Hermes Agent, codex subagent)  
**対象リポジトリ**: `agg-btc-receiver`  
**対象パイプライン**: `burst_agg/summary/*.jsonl` → 30秒サマリ行に付与するカテゴリ列

---

## 1. 目的

`burst_agg/summary/*.jsonl` の各 30 秒サマリ行について、`burst_delta_notional`（30 秒間の Burst 寄与 CVD 増分、符号付き USD notional）の絶対値に基づき、当該ウィンドウの **BurstCVD サイズランク** を下記 3 段階に分類する列を追加する。

| ランク | 意味 |
|--------|------|
| `small` | 平常的な bursts |
| `medium` | やや目立つ bursts |
| `large` | 顕著な bursts（要監視） |

方向（buy/sell）は `burst_delta_notional` の符号として別途保持。サイズランクは方向とは独立。

---

## 2. 定義（契約）

### 2.1 入力

- フィールド: `burst_delta_notional`（float, USD, 符号付き）
- 集計窓: 30 秒（`ts` 単位で 1 行 = 1 ウィンドウ）
- 計算対象: **全 `burst_agg/summary/*.jsonl` の行**（zero-burst ウィンドウを含む）

### 2.2 メトリック

```
abs_burst_delta = abs(burst_delta_notional)
```

### 2.3 グループ分割

- **spot**: 取引所名に `"perp"` を含まない全マーケット
- **perp**: 取引所名に `"perp"` を含む全マーケット
- spot と perp は**独立した閾値セット**を持つ

### 2.4 推奨閾値（v1.0）

4 案の比較に基づく推奨:

#### 推奨案: `p50_p90_balanced`（デフォルト）

| グループ | small | medium | large |
|----------|-------|--------|-------|
| **spot** | `abs_burst_delta < 14,000` | `14,000 <= abs_burst_delta < 120,000` | `abs_burst_delta >= 120,000` |
| **perp** | `abs_burst_delta < 160,000` | `160,000 <= abs_burst_delta < 1,200,000` | `abs_burst_delta >= 1,200,000` |

- カバレッジ（実測 4h サンプル）:
  - spot: small 49.5%, medium 40.5%, large 10.0%
  - perp: small 50.0%, medium 39.8%, large 10.2%

#### 代替案: `p50_p95_large_top5`（large を絞りたい場合）

| グループ | small | medium | large |
|----------|-------|--------|-------|
| **spot** | `abs_burst_delta < 14,000` | `14,000 <= abs_burst_delta < 200,000` | `abs_burst_delta >= 200,000` |
| **perp** | `abs_burst_delta < 160,000` | `160,000 <= abs_burst_delta < 2,000,000` | `abs_burst_delta >= 2,000,000` |

- spot: small 49.5%, medium 45.4%, large 5.2%
- perp: small 50.0%, medium 44.9%, large 5.1%

### 2.5 zero-burst / no-burst の扱い

現行データ（4時間サンプル）ではゼロバーストウィンドウは spot 0.5%, perp 1.5% と稀少だが、契約上は明示的に扱う:

```
abs_burst_delta == 0  →  size_rank = "none"（または "zero"）
```

- `"none"` は「当該ウィンドウに burst が検出されなかった」ことを意味する
- small/medium/large と区別し、集計時にフィルタ可能にする
- `burst_delta_notional == 0` かつ `burst_count > 0` が理論上ありうる場合（相殺）も `"none"` に分類する（`abs == 0` は常に `none`）

### 2.6 閾値の丸め方針

実用性のため、閾値は以下のルールで丸める:

```
x >= 1,000,000 → 100,000 単位（round(x / 100000) * 100000）
x >=   100,000 →  10,000 単位
x >=    10,000 →   1,000 単位
x <     10,000 →     100 単位
```

本仕様の推奨閾値 14,000 / 120,000 / 160,000 / 1,200,000 はいずれもこのルールに従っている。

## 3. 出力カラム命名（実装時）

`burst_agg/summary/*.jsonl` の各行に以下のカラムを追加する:

| カラム名 | 型 | 説明 |
|----------|-----|------|
| `burst_size_rank` | string enum | `"none"`, `"small"`, `"medium"`, `"large"` のいずれか |
| `burst_size_group` | string | `"spot"` または `"perp"`（閾値参照元、冗長だがデバッグ用） |
| `burst_abs_delta` | float | `abs(burst_delta_notional)`（計算済み、確認用） |

実装上の注意:
- `burst_size_rank` の決定ロジックは単一関数に切り出し、単体テスト可能にすること
- 閾値は定数または設定ファイル（`config/thresholds.yaml` 等）から読み込む

## 4. 再校正ポリシー

### 4.1 トリガー

以下のいずれかが発生した場合、閾値の再計算を検討する:

1. **データ蓄積**: 最低 7 日間（連続 168h）の burst_agg データが蓄積された時点で初回再校正
2. **レジーム変化**: 大幅なボラティリティシフト（BTC 価格が 20% 以上変動した日を含む週）
3. **定期**: データ蓄積後に月次で再評価（自動化推奨）
4. **取引所追加/削除**: spot/perp グループ構成が変わった場合

### 4.2 再校正手順

1. 全 `burst_agg/summary/*.jsonl` から spot/perp 別に `abs(burst_delta_notional)` の分布を収集
2. パーセンタイル `p50`, `p90`, `p95`, `p99` を再計算
3. 推奨閾値案 `p50_p90_balanced` で丸めた値を新しい閾値候補とする
4. 新旧閾値の差分が `max(t1, 丸め単位)` の 20% 以上の場合、閾値更新を実施
5. 更新時は `burst_agg/summary/` 全行を新しい閾値で再分類（`burst_size_rank_v2` 列として追加し、旧列は保持）

### 4.3 推奨しない方針

- **毎日/毎時の動的閾値更新**: 時系列比較が困難になり、シグナルの解釈が不安定になる
- **固定閾値の永続**: 市場構造変化に追随できず陳腐化する

## 5. 短期サンプルリスク評価

### 5.1 現行サンプルの限界

| 項目 | 値 | リスク |
|------|-----|-------|
| データ期間 | 約 4 時間 (2026-07-07 22:04 - 07-08 02:06 UTC) | **高** - 単一セッションのみ |
| 対象市場数 | 15 (spot 8, perp 7) | 十分だがサンプル期間が短い |
| 時間帯 | UTC 深夜（アジア早朝） | 流動性・ボラティリティが日中と異なる可能性 |
| ゼロバースト率 | spot 0.5%, perp 1.5% | 現状低いが、閑散時間帯では増加の可能性 |
| 曜日 | 火曜→水曜 | 週末/週初のパターン未捕捉 |

### 5.2 具体的リスク

1. **テール過小評価**: p99 以上（large の large）の分布が 4h では不十分。真の p99 はさらに大きい可能性
2. **レジーム依存**: 現状はレンジ〜弱含み相場。トレンド発生時の分布は未検証
3. **zero-burst 過小評価**: 閑散時間帯（週末アジア早朝等）ではゼロバースト率が上昇
4. **取引所バイアス**: Hyperliquid, Binance の perp が支配的。取引所構成の変化で閾値がシフト

### 5.3 緩和策

- v1.0 閾値は「暫定」と明示し、7 日間データ蓄積後に再校正を必須とする
- 閾値は設定ファイル化し、コード変更なしで更新可能にする
- large カテゴリの上位（p95+, p99+）の簡易集計を定期実行し、閾値の妥当性をモニタリング
- `burst_size_rank` に加えて `burst_abs_delta` の生値も常に出力し、後日任意の閾値で再分類可能にする
